# Agent: Wave-2C — DEF widget engine entry-point identification
# Date: 2026-05-16
#
# Mission: Identify the text-based DEF widget engine (parser + renderer +
# input dispatcher) that powers options/popup/savegame/loadgame/joingame/
# hostgame/ingamemenu/mpingame/selstart/createchar/userinfo/connect/
# connectsimple secondary screens, as described in
# CLASSIC_HUD_REFERENCE.md §8 and RETAIL_UI_RECOVERY_PLAN.md Tier 9.
#
# ============================================================================
# Methodology
# ============================================================================
# Step 1: Read widgets.def + per-screen .def samples (options, popup) to
#         extract distinctive vocabulary (PANEL, STYLE, BEGIN, END, BUTTON,
#         TEXT, BITMAP, SCROLLBAR, LISTBOX, DROPLIST, FRAME, EDIT, FIELD,
#         BGBITMAP, DROPBUTTON, UPLABELRECT, DOWNLABELRECT, LISTHEIGHT,
#         DRAWMODE, ITEMRECT, SPIN, FONT, FLAGS, POS, RECT, COLOR, ...).
# Step 2: FindStringRefs.java for each distinctive token across the retail
#         binary. Results in /tmp/recon_ui/refs_*.txt.
# Step 3: Cluster analysis — all distinctive widget tokens reference
#         functions in the 0x42a000-0x437xxx range, with their string
#         literals packed in the 0x005ccfb8-0x005cdc64 .rdata region. Same
#         translation unit. Decisive.
# Step 4: Decompile the cluster + the per-screen activators that load each
#         .def file. Cross-reference call chains. Verify with golden-path
#         error strings.
#
# ============================================================================
# Evidence summary (all string anchors live in 0x005ccfb8-0x005cdc70)
# ============================================================================
# Distinctive token       Address       Owner function
# ---------------------   -----------   --------------
# "PANEL"                 0x005cdb64    FUN_00437000 (panel-body parser)
# "BEGIN" (panel-local)   0x005cda78    FUN_00437000
# "END" (panel-local)     0x005cda9c    FUN_00437000
# "Panel layout BEGIN expected"  0x005cda80  FUN_00437000  ← golden-path error
# "STYLE"                 0x005cd9f8    FUN_00436ec0 (control dispatcher)
# "Control STYLE definitions not allowed in panel layout"  0x005cda00
# "Unrecognized layout command %s"  0x005cda58  FUN_00436ec0
# "Unrecognized tag in %s control"  0x005cda38  FUN_00436ec0
# "widgets.def"           0x005cdbcc    FUN_004377c0 (file loader)
# "Unable to load widgets.def"  0x005cdbe4    FUN_004377c0  ← golden-path error
# "Unable to load %s"     0x005cdc0c    FUN_004377c0
# "POS"/"%i,%i"/"NAME"/"FIELD"/"INDEX"/"TEXT"/"STRINGREF"/"FLAGS"/"GROUP"/"HOTKEY"
#                         0x005ccfb8.. 0x005cd09c    FUN_0042a350 (TWidget base ctor)
# "BITMAP"/"DRAWMODE"     0x005cd0f0+   FUN_0042aaf0 (BITMAP widget ctor)
# "BGBITMAP"/"FRAME"/"FONT"  0x005cd158+  FUN_0042b340 (TEXT widget ctor)
# "UPLABELRECT"/"DOWNLABELRECT"  0x005cd264/0x005cd288  FUN_0042bd90 (BUTTON ctor)

# "DROPBUTTON"/"ITEMRECT"/"LISTHEIGHT"  0x005cd814+  FUN_00433170 (DROPLIST ctor)
#
# All widget-type and attribute strings live in one contiguous .rdata window
# referenced by one contiguous .text window — clear evidence of one TU.
#
# ============================================================================
# Architecture (inferred)
# ============================================================================
#
#  ┌───────────────────────────── PER-SCREEN ACTIVATOR ──────────────────────┐
#  │  FUN_005399f0  (savegame), FUN_00465a50 (createchar), etc.              │
#  │  builds geometry + sprite names, calls:                                  │
#  └────────────────────────────┬────────────────────────────────────────────┘
#                               │
#  ┌────────────────────────────▼────────────────────────────────────────────┐
#  │  FUN_00435150  DefScreen_Open(name, panel, flags, x,y,w,h, ..., bg)     │
#  │  high-level "open this DEF screen" entry (modal centred)                 │
#  └────────────────────────────┬────────────────────────────────────────────┘
#                               │
#  ┌────────────────────────────▼────────────────────────────────────────────┐
#  │  FUN_00435040  DefScreen_LoadAndShow                                     │
#  │  generic init: strips ".def", appends ".def", calls LoadFile, then      │
#  │  activates via vtable+0x2c                                               │
#  └────────────────────────────┬────────────────────────────────────────────┘
#                               │
#  ┌────────────────────────────▼────────────────────────────────────────────┐
#  │  FUN_004377c0  DefWidget_LoadFile(this, "name.def")                     │
#  │  ENGINE ENTRY: loads widgets.def + per-screen.def, concatenates into    │
#  │  this->buf at +0xc8 (size at +0xcc), strncpy(this->name, name, 0x7f).   │
#  │  String anchor: "widgets.def", "Unable to load widgets.def",            │
#  │  "Unable to load %s". DECISIVE.                                          │
#  └────────────────────────────┬────────────────────────────────────────────┘
#                               │
#                  (later, often same activator:)
#                               │
#  ┌────────────────────────────▼────────────────────────────────────────────┐
#  │  FUN_00437620  DefWidget_ParseBuffer(this)                              │
#  │  PARSER ENTRY: opens a TString tokenizer over this->buf, dispatches     │
#  │  to vtable+0xb4 (the screen's parse hook), then activates via +0x94.    │
#  │  Reads buffer pointer/size from this+0xc8/+0xcc set by LoadFile.        │
#  └────────────────────────────┬────────────────────────────────────────────┘
#                               │
#                  vtable+0xb4 → (panel/style discriminator)
#                               │
#  ┌─────────────┬──────────────┴──────────────┐
#  │             │                              │
#  ▼             ▼                              ▼
# FUN_00437000  FUN_00436ec0          [STYLE section parser]
# PANEL parser  CONTROL DISPATCHER     (registers named styles into
# expects BEGIN  reads identifier      DAT_00655510 table; STYLE-ref
# loops calling  token, looks up in    consumer is FUN_00436ec0 itself)
# +0xac per      DAT_00655510 widget-
# control until  class table by name
# END            (count DAT_0065617c),
#                calls registered
#                constructor func ptr
#                via vtable[0] on
#                the class entry.
#
#  ┌─────────────────────────────────────────────────────────────────────────┐
#  │  WIDGET-SUBCLASS CONSTRUCTORS (one each, registered into global table)  │
#  │  FUN_0042a350 — TWidget base attrs (POS/SIZE/NAME/FIELD/TEXT/FLAGS/…)   │
#  │  FUN_0042aaf0 — BITMAP                                                  │
#  │  FUN_0042aed0 — (FRAME-bitmap variant)                                  │
#  │  FUN_0042b340 — TEXT                                                    │
#  │  FUN_0042bd90 — BUTTON                                                  │
#  │  FUN_0042d730 — FRAME                                                   │
#  │  FUN_0042f700 — LISTBOX FIELD/END inner format-block                    │
#  │  FUN_0042f9f0 — LISTBOX                                                 │
#  │  FUN_00431750 — EDIT (with SPIN sub-mode)                               │
#  │  FUN_00433170 — DROPLIST                                                │
#  └─────────────────────────────────────────────────────────────────────────┘
#
#  ┌─────────────────────────────────────────────────────────────────────────┐
#  │  INPUT DISPATCH                                                         │
#  │  FUN_004361f0  DefWidget_DispatchInput(this, vkey, isKeyDown)           │
#  │  Walks this->children[] (count +0x88, array +0x98). On 'R' (0x52)       │
#  │  hot-reloads via FUN_004377c0(this->name) — DEV FEATURE; on arrow       │
#  │  keys (0x25..0x28) navigates focus; on Enter (0xd) calls focused's      │
#  │  vtable+0x2c (activate). For unhandled, iterates children calling each  │
#  │  one's vtable+0x58 (KeyDown handler).                                   │
#  └─────────────────────────────────────────────────────────────────────────┘
#
# ============================================================================
# Conservative rename rules applied here
# ============================================================================
# - Engine entry points (LoadFile, ParseBuffer, ParsePanel, DispatchControl,
#   DispatchInput, TWidget base ctor) have 2+ independent evidence lines each
#   (string anchor + call-chain match + cross-reference).
# - Per-screen activators are renamed ONLY for those screens whose .def file
#   appears as a string literal in the binary AND whose call chain hits
#   FUN_004377c0 (connect, connectsimple) — these are DOUBLE-confirmed.
# - For screens whose .def filename is built at runtime (savegame, loadgame,
#   options, popup, hostgame, joingame, mpingame, selstart, createchar,
#   userinfo, ingamemenu, exit — all routed through FUN_00435150 with a
#   "savegame"/"options"/etc. base-name parameter), the activator is renamed
#   because the bare base name appears as a string literal AND it is passed
#   into FUN_00435150 (which routes to FUN_004377c0).
# - Widget-subclass constructors get a "_ParseAttrs" suffix — they don't get
#   class names yet, because each one would need vtable confirmation and
#   that's a separate hunt. The base-class TWidget identification stays
#   in the brief as "primary candidate, needs vtable+ctor signature
#   confirmation against any pre-release src class definition."
# - The big "DEF top-level dispatch" function in the 0x437080-0x437620 gap
#   (where the STYLE-section parser body lives) is NOT renamed — it's a
#   single bare region Ghidra didn't bind to a function entry; needs a
#   force-CreateFunction first. Documented in the brief.
#
