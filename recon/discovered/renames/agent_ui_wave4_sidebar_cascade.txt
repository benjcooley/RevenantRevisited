# Vtable @ 0x005a5750 dumped to recon/discovered/cls_0x5a5750_vtable.txt

# Vtable slot 1 = Close. Frees 3 mosaic surfaces at +0x188/0x18c/0x190
# (these are the 3 buffers allocated in Initialize @ 0x53cc30 lines 30-138).
# Then calls FUN_00434f30 = TButtonPane intermediate Close.
# Two lines of evidence: (a) vtable slot 1 of every TPane derivative is
# Close (= base TPane Close at 0x491970); the leaf override pattern of
# "free children then call base Close" is universal. (b) the freed pointers
# are exactly the 3 surfaces allocated by Initialize.
FUN_0053d360|FUN_0053d360_TSideTabsPane_Close

# Vtable slot 19 = Update / per-tick animate. Walks `this->buttons` array
# (param_1 + 0x88 = count, param_1 + 0x1ac = first slot) and steps each
# button's hover-fade state (slot[6]) toward target (0 or 8 based on flag
# byte at button+0x14 bit 3 = "hovered"). Slot[0] is the current alpha
# value, ramping +/-1 per tick.
# Two lines of evidence: (a) the slot 19 (Animate/Update) position matches
# TButtonPane convention per docs/ui/briefs/B_r6_button_pane.md analysis.
# (b) the per-button slot[6]=target, slot[0]=current, +/-1 stepping is a
# textbook hover-fade animation pattern; matches the alpha multiplier
# (param_1 * 0xff >> 3) used in slot 7 (DrawBackground) which renders
# each button with fade alpha.
FUN_0053d3a0|FUN_0053d3a0_TSideTabsPane_Update

# Vtable slot 7 = DrawBackground (per-button fade-alpha bitmap blit).
# Reads same per-button slot[0] alpha state that slot 19 advances and
# composites each button's bitmap (button+0x68/0x6c size, +0x60/0x64
# position) with fade alpha. Inactive draw pass.
# Two lines of evidence: (a) the alpha-fade rendering corresponds 1:1 with
# the state ramp in slot 19. (b) the FUN_00414d70 call signature matches
# the universal HUD-blit primitive used by TPane subclasses for sprite
# composition.
FUN_0053d420|FUN_0053d420_TSideTabsPane_DrawBackground

# Vtable slot 23 = Draw (main pass). Composites the same per-button
# bitmap stack as DrawBackground but with extra width (>0x80 fade
# threshold for the bright pass) into the active surface @ +400 (= +0x190).
# This is the "selected/active button gets the bright treatment" pass.
# Two lines of evidence: (a) slot 23 is the TButtonPane main-draw slot
# convention. (b) the explicit threshold `0x80 < iVar2` to gate the
# bright pass is consistent with "draw the active button differently"
# style of state-driven multi-pass button rendering.
FUN_0053d540|FUN_0053d540_TSideTabsPane_Draw

# Vtable slot 25 = MouseClick. Tests for mouse event type 4/5 and bounds,
# then marks 3 global dirty flags (_DAT_0065d548, _DAT_0065b078, _DAT_0065b830)
# so HUD overlays know to re-render after the sidebar paints over them.
# Falls through to FUN_00436530 = TButtonPane intermediate per-button
# callback pump, which is where the actual per-button click routing
# happens (button callbacks were registered via FUN_00436790 in Init).
# Two lines of evidence: (a) param_2 values 4 and 5 are the mouse-down /
# mouse-up event-type IDs used universally by the input dispatcher
# (see FUN_004361f0 = DefWidget_DispatchInput per B.r7). (b) the
# pattern of "test bounds + check 3 visibility globals + early-out
# unless something is showing" is consistent with a HUD click handler
# that only kicks the dirty-flag system when there's actually content
# to invalidate.
FUN_0053d6e0|FUN_0053d6e0_TSideTabsPane_MouseClick
