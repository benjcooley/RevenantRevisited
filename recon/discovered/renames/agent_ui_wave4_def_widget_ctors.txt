# Agent: Wave-4C — DEF widget class roster + true parse-time ctors
# Date: 2026-05-17
#
# Mission (4C.1): Pin the per-widget true ctors for all 8 widget classes
# registered into DAT_00655510. Wave-3C confirmed SCROLLBAR alone but
# misidentified its address (cited FUN_0042de00, actual ctor is FUN_0042df00
# — see §4 below).
#
# ============================================================================
# Architecture refinement (corrects both Wave-2C and Wave-3C)
# ============================================================================
#
# The DAT_00655510 registry holds 8 records, each:
#     +0x00 : pointer to a 3-slot "class descriptor vtable" in .rdata (0x5a3xxx)
#     +0x04 : ASCII name C-string
#
# The class descriptor vtables are uniformly 0x6c (108 bytes) apart, packed
# adjacent in .rdata from 0x5a3b18..0x5a3e10. Each class descriptor is just
# 3 fnptrs: [0] = parse-time factory, [1..2] = related per-class helpers.
#
# DefWidget_DispatchControl (0x436ec0) calls the FACTORY at registry_vt[0]
# with signature `(pane, token)`. Each factory is a 106-byte trampoline:
#     iVar1 = operator_new(SIZE_OF_WIDGET, this);     // FUN_00482fb0
#     if (iVar1 != 0) return REAL_CTOR(pane, token, 0);
#     return 0;
#
# The REAL_CTOR is the per-widget parse-time ctor we're after. It:
#     (a) Calls FUN_0042a350(pane, TYPE_ID, token)
#         — the shared TDefWidget_BaseInit / TWidgetBase_ParseAttrs that
#         sets *this = &PTR_FUN_005a3ab8 (TWidget base instance vtable) and
#         parses POS/SIZE/NAME/FIELD/INDEX/TEXT/STRINGREF/FLAGS/GROUP/HOTKEY.
#     (b) Overwrites *this = &PTR_FUN_005a3xxx  -- the per-class INSTANCE
#         vtable for this widget subclass.
#     (c) Initializes subclass-specific fields.
#
# Note that there are TWO disjoint vtable families:
#     - REGISTRY descriptor vtables (3 slots) at 0x5a3b18, 0x5a3b84, 0x5a3bf0,
#       0x5a3c5c, 0x5a3ccc, 0x5a3d38, 0x5a3da4, 0x5a3e10.
#     - INSTANCE per-class vtables (24+ slots) at 0x5a3ab8 (TWidget base),
#       0x5a3b24, 0x5a3b90, 0x5a3bfc, 0x5a3c68, 0x5a3cd8, 0x5a3d44, 0x5a3db0,
#       0x5a3e1c (the 8 widget subclass instance vtables).
#
# Wave-3C inspected the instance vtables (correctly) but confused them with
# the registry vtables. The "vtable[0] is the dtor" Wave-3C noted for slot 0
# of 0x5a3ab8 / 0x5a3cd8 is correct -- but those are INSTANCE vtables. The
# registry vtables' slot 0 is the FACTORY, not the dtor.
#
# ============================================================================
# Confirmed widget roster (golden-path pattern: factory+ctor+vtable)
# ============================================================================
#

#
# Confidence: HIGH for all 8 -- each has 3 independent lines of evidence:
#   1. Record address from FindImmRefs.java on each record_addr (shows the
#      thunk's MOV that writes record into registry, plus the MOV that writes
#      registry vtable_ptr into record[0]).
#   2. RegVT slot 0 (factory) extracted via DumpBytes.java + decomp: every
#      factory body is the same 106-byte allocate-and-construct shape:
#          op_new(SIZE_OF_WIDGET, this) → ctor(pane, token, 0)
#   3. Ctor body has the canonical (FUN_0042a350(pane, TYPE_ID, token);
#      *this = 0x5a3xxx; field defaults) shape.
#
# The FRAME identification (record 0x655508) was confirmed by reading the
# string at the register thunk: 0x42aead `MOV [0x65550c], 0x5cdc30`, and
# DumpBytes 0x5cdc30 → "FRAME\0\0\0TEXT\0\0\0\0" -- the name string IS "FRAME".
# This corrects Wave-3C's tentative "BGBITMAP-helper" labeling for this slot.
#
