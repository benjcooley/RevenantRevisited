# Source raster channels and FireFlash normal space

The original software raster now supplies causal tests for two shared renderer
corrections. These are not whole-effect visual acceptance or a replacement for
the remaining projection, framebuffer precision and natural-spell gates.

`test_argb4444.py` executes the unchanged retail EXE. All 65,536 entries from
`56ca90` convert ARGB4444 color nibbles to RGB565 as R/B ×2 and G ×4, without
bit replication. The executed `54fbf2` kernel uses `(alpha_nibble+1)/16`, not
normalized alpha `/15` or alpha `/16`. Its channel result is
`dst-floor(dst*a/16)+floor(src*a/16)`, with `a=alpha_nibble+1`. 384 rendered
alpha/color/background controls match this formula. In particular, alpha0
is not discarded and full white converts to `0xf79e`, not `0xffff`.

A new software lighting mode3 is selected only for exact 16-bit masks
R=`0xf00`, G=`0xf0`, B=`0xf`, A=`0xf000`. Mode2 keeps the prior normalized
alpha behavior for other formats. Hardware/modern mesh policy demotes3 to2.
The audited Warp atlas also selects3. Metal, GLSL and HLSL mesh/helper shaders
recover exact nibbles and supply the source RGB565/alpha values. Integer
**destination** rounding is still absent from the RGBA8 GPU blend and remains
an explicit device discrepancy.

Applying minimum alpha in the G-buffer exposed a second causal issue: writing
an unlit effect normal on a translucent black texel changes the lighting of the
underlying floor. Exact4444 software meshes now blend after scene lighting,
in authored triangle order, with positive screen-down culling, depth test and
writes. They bypass the character nearest-surface depth prepass. Modern and
other-format paths keep their existing policy. This route shares the existing
transparent pass's lack of G-buffer picking/normal output; interleaving with
other transparent objects and native per-triangle depth remain separate gates.

For RGB565, 2,048 original Scene-mode8 rendered texel/light/background cases
establish five-bit texture modulation divided by31. Green first uses its high
five texture bits. Additive source and destination channels have their low bit
cleared before saturating addition. The source rounding/low-bit threshold is
now used in software RGB565 helper shading. The GPU still does not clear the
destination's low bits. Neither a `/32` brightness fit nor a blanket material
color substitution is used.

`LitSoftwareFixture` also now executes the omitted original startup call
`54df70` with tables generated by `56c730`; these camera tables are required by
the RGB565 additive path. Its regression calls original Scene mode8 and the
original RGB565 raster rather than injecting an additive metadata assumption.

FireFlash's common-world geometry bridge scales Z by1.5 (1.46 in ABSPOS).
Actual native owner fragments `40e470..40e546`/`40e740..40e83d` have an identity
Z basis; facing rotates XY only. Applying the geometry bridge to normals
incorrectly changed the retained scene's five-bit illumination from9 to4.
FireFlash now passes the inverse of its explicit geometry-only bridge for
source normal normalization. Geometry, simulation, texture, tint and timing
are unchanged. `test_fireflash.py` retains the 150-record/101-sample state proof
and compares all596 authored vertices at tick30 against actual native owner,
RenderObject and Illuminate. Omitting the normal bridge fails this comparison.
This bounded null-target test does not close natural target/ABSPOS behavior.

### Follow-up: original alpha scene state

The initial post-light mode3 pipeline incorrectly retained depth writes and
back-face culling. Executed `NewObject409ca0` assigns both Ribbon subobjects
`flags=0x01000000, blend=4` when their used texture carries alpha. The decoded
resource boundary supplies literal names, material indices and texture-face
counts; material values do not affect this branch (both branches join409eb1).
Removing the alpha metadata is a negative control: no blend override is assigned.
Executing the actual `RenderObject40adfc..40aeba` dispatch on those constructed
objects, including unmodified `Scene.SetBlendMode417d60`, yields ZWRITE0,
ZENABLE1, CULL_NONE, SRCALPHA/INVSRCALPHA. This holds for all14 subobjects of the
seven pinned Ribbon assets. Original4444 raster controls render both windings
and blend a rear layer after a front layer; forcing depth writes suppresses the
rear layer. `test_alpha_scene_state.py` preserves these controls.

The static software mode3 pipeline now tests existing scene depth without writing
it and renders both face directions. Warp's explicit helper depth policy is
unchanged. This evidence establishes caller state and raster behavior, not a
whole-scene lighting or pixel-identical GPU claim.
