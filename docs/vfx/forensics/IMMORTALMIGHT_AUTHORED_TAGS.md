## Constructor alpha prerequisite: concrete correction

The [first completed pair](</Users/benjamincooley/RevenantRetailLab/captures/ab/sw-fps-immortalmight-quality1-actual-map-20261005/comparison.png>) visibly exposes the port's opaque near-black flare halo. Appearance remains unaccepted. The bounded audit found a source association error rather than a justification for a fitted alpha or brightness.

NewObject `409e57` reads the loaded texture descriptor at `+0x64`, its `dwRGBAlphaBitMask`; `409e5a–409e5c` skips the **entire** material/mode4 block when this mask is zero. The source software closest-format function preserves no-alpha RGB565. Exact Imight has alpha mask0, so its specular/emissive values do not select mode4. Eight executions of the [unmodified constructor fragment](</Users/benjamincooley/RevenantRetailLab/research/next-buff-immortalmight-20261005/base-alpha-prerequisite-correction.json>) pass across alpha/no-alpha textures, zero/nonzero emissive and initial camera flags. No-alpha cases retain blend0 and add no `OBJ3D_BLEND`; alpha textures select mode4. The initial provenance report is retained, with this correction taking precedence.

There is also no material-derived vertex-alpha scalar: normal FVF `0x112` processing writes literal alpha5=31 at `56f0e9`. A specular0.9 alpha adjustment would be invented.

For the steady live-particle case, particle Render `4026dc–4026e9` writes controller mode16 to its prototype, RenderObject changes scene blend only under `OBJ3D_BLEND` (`40ae03`), and controller Render `404270–4042d6` returns without restoring blend. The subsequent RGB565 `#flare`, lacking that flag, therefore inherits the particle's ONE/ONE mode16. The source correction removes forced mode4/`OBJ3D_BLEND`, keeps the camera flag and uses the existing additive after-FX handoff for that inherited state. Shader, alpha, texture, physics and appearance fitting are unnecessary for this identified error.
